# ChatGPT Work / Sites 部署方案讨论（2026-07-25 14:11）

## 用户需求

用户希望把当前本地交易看板部署到 ChatGPT Work，以便不依赖本机持续开机并可在手机访问。

## 结论

- ChatGPT Work 的 Sites 是最合适的发布入口；当前 `127.0.0.1:8765` 不能直接上传或分享。
- 当前看板不是纯静态页面：Python 服务会读取本机 `交易记录.xlsx`、`日记/`、`/Users/liuguan1/Documents/New project 2` 日报目录和本地风控模型目录，并执行 Python 子进程。Sites 云端无法访问这些本地路径，也不能原样运行现有 Python 后端。
- 需要采用迁移而不是简单发布：前端迁移到 Sites 兼容运行时；交易记录、日记和报告索引迁移到 D1/R2；Tushare 等凭证进入托管密钥；风控模型作为独立 Python 服务或定时产出 JSON 后推送到云端。
- 建议默认使用 ChatGPT 登录保护和私有/工作区访问，避免交易记录、持仓、日记和 API 凭证公开。
- 若后续希望在 ChatGPT 对话中直接查询持仓、复盘和日记，可在网站稳定后再增加自定义 MCP/ChatGPT App；这不是第一阶段上线的必需项。

## 推荐实施顺序

1. 复制出独立的云端 Sites 版本，保留当前本地看板作为回退，不直接破坏现有服务。
2. 迁移页面与只读数据接口，先发布受保护的移动端可用版本。
3. 增加 Excel 导入/同步、日记云端保存、每日报告自动推送。
4. 把风控模型的 Python 重跑留在独立服务或自动任务中，只向 Sites 写入正式 JSON 结果。
5. 最后再接入 ChatGPT App/MCP，实现对话式查询和操作。
